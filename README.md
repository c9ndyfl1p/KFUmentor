# AI Job Agent

Локальный MVP для поиска вакансий на hh.ru и первичной оценки их соответствия профилю кандидата. Проект написан на Go, управляет Chromium через Playwright и обращается к локальной модели Ollama.

## Что работает сейчас

- Поиск вакансий на hh.ru по запросу.
- Извлечение карточек вакансий и оценка соответствия через Ollama.
- Подготовка сопроводительного письма.
- Отправка откликов только при явном включении `--auto-apply`.
- Постоянный профиль Chromium для входа пользователя в hh.ru.
- Импорт профиля из JSON, текстового PDF и Word DOCX с проверкой перед сохранением.

Это пока не автономная платформа из концепции: нет регистрации и кабинета, базы данных кандидатов, очереди фоновых задач, интеграций с почтой/календарём, HR-переписки, подготовки и аналитики интервью, сопровождения офферов и биллинга. Браузерная автоматизация может ломаться при изменениях сайта. CAPTCHA и запросы на подтверждение нужно проходить вручную.

## Подключение ИИ через Ollama

Агент уже использует Ollama как ИИ-сервер: отдельный API-ключ для локальной модели не нужен. Модель работает на вашем компьютере; для её первоначальной загрузки нужен интернет. Этот проект вызывает Ollama API (`/api/generate` и `/api/chat`), а не ChatGPT/OpenAI API.

1. Установите Ollama с [официального сайта](https://ollama.com/download).
2. Откройте приложение Ollama. Если вы запускаете Ollama из терминала и сервер ещё не работает, выполните `ollama serve` в отдельном окне терминала.
3. Загрузите модель, которую проект использует по умолчанию:

   ```bash
   ollama pull qwen2.5:7b
   ```

   Файл модели занимает около 4,7 ГБ; понадобятся дополнительное место для временных файлов и память для запуска модели. [Страница модели и варианты размеров](https://ollama.com/library/qwen2.5).

4. Убедитесь, что Ollama запущен и модель установлена:

   ```bash
   ollama list
   curl http://localhost:11434/api/tags
   ```

5. Запустите панель проекта:

   ```bash
   go run . --web
   ```

   Откройте [http://localhost:8787](http://localhost:8787). При запуске приложение подключится к Ollama по адресу `http://localhost:11434` и будет использовать `qwen2.5:7b`.

Если выбрали другую модель, сначала загрузите её командой `ollama pull ИМЯ_МОДЕЛИ`, затем передайте это же имя приложению. Например:

```bash
go run . --web --model=qwen2.5:3b
```

Если Ollama работает на другом адресе или порту, укажите базовый адрес без `/api`:

```bash
go run . --web --model-url=http://127.0.0.1:11434 --model=qwen2.5:7b
```

В локальной панели адрес и модель не задаются; их нужно указать в команде до запуска панели. Адрес `--model-url` должен быть доступен именно той машине, где выполняется агент. При ошибке соединения проверьте, что Ollama запущен, `ollama list` показывает нужную модель, а сервер принимает запросы на `11434`.

## Требования

- Go 1.24 или новее.
- Ollama и загруженная модель, например `qwen2.5:7b` (инструкция выше).
- Chromium/Playwright. При первом запуске библиотека Playwright может установить драйвер; браузер устанавливается командой ниже.

```bash
go run github.com/mxschmitt/playwright-go/cmd/playwright@v0.6201.1 install chromium
```

На Linux системные библиотеки Chromium при необходимости установите по инструкциям Playwright для вашей ОС.

## Профиль кандидата

Отредактируйте `data/resume.json` или создайте отдельную копию профиля. Файл должен содержать ваши реальные данные; пример в репозитории демонстрационный. Не коммитьте персональный профиль.

```json
{
  "name": "Имя Фамилия",
  "title": "Backend-разработчик",
  "summary": "Краткое профессиональное описание",
  "experience": [
    {
      "position": "Backend-разработчик",
      "company": "Компания",
      "period": "2022–2025",
      "responsibilities": ["Разрабатывал сервисы на Go", "Поддерживал PostgreSQL"]
    }
  ],
  "skills": ["Go", "PostgreSQL", "Docker"],
  "education": [],
  "languages": [],
  "contact": {
    "email": "name@example.com",
    "phone": "+7 ...",
    "linkedin": "",
    "github": ""
  }
}
```

Перед отправкой откликов программа проверяет наличие имени, должности и навыков. Персональные поля из этого файла не используются для входа в аккаунт: авторизуйтесь вручную в открытом Chromium.

## Использование

### Локальная панель управления

Запустите из корня проекта:

```bash
go run . --web
```

Откройте [http://localhost:8787](http://localhost:8787). В панели можно заполнить профиль, запустить поиск, посмотреть вывод агента и отдельно включить автоотклики. Чтобы войти в hh.ru без запуска поиска, нажмите **«Только войти на hh.ru»**. Агент откроет отдельное окно и не будет переключать страницу или продолжать поиск; после входа закройте окно, чтобы сохранить сессию. В разделе профиля нажмите **«Прикрепить резюме»**, чтобы импортировать JSON, текстовый PDF или Word DOCX размером до 10 МБ. PDF поддерживается до 20 страниц и 24 000 символов извлечённого текста. Для PDF и DOCX нужна запущенная локальная модель. Сначала откроется редактируемый предпросмотр; текущий профиль заменится только после нажатия «Сохранить профиль». Сканы PDF без текстового слоя и старый формат DOC пока не поддерживаются. Профиль из панели хранится в `data/resume.local.json` и не попадёт в Git.

Остановить локальный сервер: `Ctrl+C` в терминале.

Запустить панель на другом локальном порту можно так:

```bash
go run . --web --web-addr=127.0.0.1:9000
```

Интерфейс доступен только на локальном компьютере.

### Командная строка

Сначала запустите поиск без отправки откликов:

```bash
go run . --task="найди вакансии Go-разработчика в Москве" --headless=false
```

Открыть hh.ru только для ручного входа, без поиска:

```bash
go run . --login-only
```

При первом запуске войдите в hh.ru в открытом браузере. Сессия хранится локально в `~/.ai-job-agent/profile`.

Для явной отправки откликов по результатам AI-оценки:

```bash
go run . --task="найди вакансии Go-разработчика в Москве" --headless=false --auto-apply
```

Укажите другой профиль кандидата или сервер/модель Ollama:

```bash
go run . --task="найди удалённую работу" --resume="./my-resume.json" --model-url="http://localhost:11434" --model="qwen2.5:7b"
```

Основные параметры: `--web`, `--web-addr`, `--task`, `--headless`, `--auto-apply`, `--debug`, `--profile`, `--resume`, `--model-url`, `--model`, `--interactive`.

В локальной панели начните вводить город или регион и выберите подсказку hh.ru. Список загружается из актуального справочника hh.ru и включает все регионы, доступные для поиска. При запуске из командной строки можно указать регион через `--area` (например, `--area=88` для Казани; `113` — вся Россия).

## Безопасное использование

- По умолчанию `--auto-apply` выключен. Без флага сгенерированный AI-план не отправляет отклики.
- Сначала проверяйте вакансии и письма вручную; модель может ошибаться.
- Не храните в репозитории персональные данные, cookies или другие секреты.
- Не обходите CAPTCHA и ограничения сайта; если сайт просит подтверждение, выполните его вручную.


## Разбор задачи и персональные письма

Агент обращается к выбранной модели для преобразования задачи в 1–3 коротких
поисковых запроса. Например, «хочу работу с машинным обучением» превращается в
ML Engineer / Machine Learning Engineer / машинное обучение. Запросы видны в
выводе агента. При недоступности модели работает резервный локальный разбор.
Город определяется по исходной задаче. Найденные вакансии объединяются без
повторов; количество задаётся фразой «найди 5 вакансий», по умолчанию — 5.

Перед оценкой агент открывает описание каждой вакансии. Модель получает текст
описания и профиль кандидата. Для релевантных вакансий выводится черновик письма
даже без автооткликов. Включение автооткликов по-прежнему требуется отдельно.
Письмо проходит отдельную проверку утверждений по резюме. При замечаниях модель
переписывает его один раз. Если замечания остаются, используется короткий
вариант, составленный из фактов профиля. Если описание, генерация или проверка
недоступны, отправка для этой вакансии отменяется. Проверка другой модельной
генерацией не гарантирует точность: перед использованием прочитайте черновик.

Чтобы задать свой стиль, создайте рядом с используемым JSON-резюме файл
`cover-letter-examples.local.json` (для панели: `data/cover-letter-examples.local.json`):

```json
[
  {
    "vacancy": "Краткое описание вакансии, для которой было написано письмо",
    "letter": "Текст одобренного вами сопроводительного письма"
  }
]
```

Можно использовать до 5 примеров. Они задают стиль, а факты о кандидате берутся
только из текущего резюме. Это передача примеров в запросе, а не дообучение весов.
Личный файл примеров исключён из Git. Отсутствие файла допускается.

Запуск с вашей моделью:

```bash
go run . --web --model=qwen3.5:4b-q4_K_M
```


## Импорт PDF и Word с предпросмотром

1. Нажмите «Прикрепить резюме» и выберите `.pdf`, `.docx` или `.json`.
2. Для PDF и DOCX программа извлечёт текст локально и передаст его выбранной
   модели через Ollama. JSON проверяется без модели. Разбор может занять до 3 минут.
3. Проверьте имя, должность, навыки, опыт, проекты, образование, языки и контакты.
   Каждый раздел можно исправить; доступны проверенные цитаты и исходный текст.
4. Нажмите «Сохранить профиль». «Отмена» и закрытие окна не изменяют прежний профиль.

Исходный документ не сохраняется и не загружается на hh.ru. Результат хранится
в `data/resume.local.json`, как и прежде. Примеры цитат подтверждают наличие текста
в документе, но не гарантируют, что модель правильно связала все сведения: проверьте
особенно даты, компании и статус учебных проектов.

В профиле появился отдельный список `projects`:

```json
{
  "projects": [
    {
      "name": "Классификация текстов",
      "description": "Учебный проект по обработке текстов",
      "technologies": ["Python"],
      "link": ""
    }
  ]
}
```

Это фрагмент профиля, а не отдельный обязательный формат файла. Старые JSON-профили
без `projects` продолжают работать. Все подробные разделы можно повторно открыть
кнопкой «Все разделы профиля»; обычное сохранение неизменённых полей сохраняет
структуру импортированного опыта, ссылки проектов, образование и контакты.

Для сканированного PDF сначала выполните OCR или экспортируйте текстовый PDF/DOCX.
DOC можно пересохранить в DOCX в Word. При недоступной модели, повреждённом файле
или превышении лимитов существующий профиль остаётся без изменений.


### Личные достижения

Конкурсы, олимпиады, хакатоны, награды и результаты участия импортируются
в отдельный раздел `achievements`, а не в образование. У записи есть поля
`name`, `result`, `date`, `organizer`, `link`. Модель не должна превращать участие
в победу или придумывать призовое место. Раздел доступен в предпросмотре, на
основной панели и через «Все разделы профиля». Старые профили без этого поля
продолжают работать. Ранее сохранённые записи автоматически не перераспределяются:
повторно импортируйте документ или исправьте нужные разделы вручную.


## Желаемое количество откликов

Включите «Отправлять отклики» и укажите желаемое количество от 1 до 100
(по умолчанию — 5). Это число успешных новых откликов, а не число просмотренных
вакансий. После достижения цели агент останавливается. Текст задачи не включает
отправку сам по себе: переключатель или флаг `--auto-apply` по-прежнему обязателен.

Агент переходит к следующим страницам поиска и не считает одну вакансию дважды
при совпадении разных поисковых запросов. Отсеиваются неподходящие вакансии и
уже отправленные отклики, если hh.ru показывает соответствующий статус.
За один запуск проверяется до 10 страниц на каждый поисковый запрос. Если
подходящих вакансий меньше цели, в отчёте будет фактическое число и недобор.
При неподтверждённой отправке запуск останавливается: проверьте «Мои отклики»
на hh.ru перед повтором. Три ошибки оценки подряд также останавливают запуск.

Из командной строки:

```bash
go run . --task="найди вакансии ML-инженера" --auto-apply --application-target=10 --headless=false --model=qwen3.5:4b-q4_K_M
```

Без автооткликов число не включает отправку и не меняет обычный поиск с черновиками.
